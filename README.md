# IP Guard

[![Release](https://img.shields.io/github/v/release/chxcodepro/ip-guard)](https://github.com/chxcodepro/ip-guard/releases/latest)
[![Windows Build](https://github.com/chxcodepro/ip-guard/actions/workflows/release.yml/badge.svg)](https://github.com/chxcodepro/ip-guard/actions/workflows/release.yml)
![Platform](https://img.shields.io/badge/Windows-10%20%2F%2011%20x64-0078D4)

面向 Windows 的公网 IPv4 防护工具。锁定允许的 Claude AI 出口 IPv4，在受保护会话启动前校验，运行期间持续监测；地址异常时暂停受控应用联网，保留进程。应用防护覆盖 Claude npm、原生 claude.exe 与 Claude Desktop；Chrome / Edge 插件仅保护 claude.ai 网页。

## 功能特性

- **IP 锁定与持续防护**：支持多个允许 IPv4，启动前校验；网络变化或获取失败时暂停应用联网，校验通过后自动恢复，保留进程与窗口。
- **防护提醒**：暂停、恢复及守护故障弹窗显示原因与受影响程序，IP 默认脱敏。
- **原终端体验**：保留控制台输入输出、工作目录、环境及退出码；同一受保护进程树的内部调用复用首次许可。
- **逐程序可选增强**：每个 EXE 独立提供基础防护与「本机 IP 防泄露」开关，增强默认关闭。
- **Claude 安装识别**：提供 npm、独立原生安装版和 Desktop 路径预设，也支持手动添加 EXE。
- **跟随当前网络**：默认沿用现有代理 / TUN 与应用代理环境，锁定出口 IPv4 后直接开启防护。
- **自动专用路由**：从受支持的本机 Xray / sing-box 核心取得当前节点，为增强入口自动建立强制代理通道，普通应用保留原分流。
- **程序管理**：编辑名称与启动参数，查看运行状态，确认后停止 Claude 进程树。
- **Claude 网页防护**：Chrome / Edge 插件按锁定 IPv4 放行 Claude 网页，浏览器代理与官方 Claude 插件保持原设置。
- **网络诊断**：展示 IPv6、网卡、DNS、时区、地区、连通性和风险属性。
- **桌面集成**：浅色 / 深色 / 系统主题、托盘运行、登录自启动和 GitHub Releases 更新。

| 文件                          | 用途                                        |

运行环境：

- Windows 10 / 11 x64。
- 管理应用防护需要管理员权限。
- Windows 防火墙的域、专用、公用三个配置文件均需启用。

> [!WARNING]
> 安装或更新、取消 IP 锁定、停止进程及退出 IP Guard 会结束相关受保护程序，请先保存工作。
>
> 安装包当前未配置代码签名，Windows 可能显示未知发布者提示。

## 快速开始

先按原来的方式连接代理工具，保持应用原有代理设置或 TUN，再完成以下操作。可选增强自动识别受支持的本机代理核心，旧手动独立节点只保留已有配置的管理。

1. 安装并打开 IP Guard；若显示普通权限，点击「以管理员身份重启」。
2. 在「允许的公网 IPv4」旁点击「获取当前 IPv4」，或每行填写一个允许地址，核对后点击「锁定」。最多 32 个，命中任意一个即可放行；获取按钮将当前地址添加到草稿并去重，锁定后才应用规则。
3. 关闭目标程序，在「受保护程序」中选择 Claude 预设或浏览 EXE，添加后开启防护开关。
4. 从 IP Guard、原快捷方式或原终端命令启动程序。
5. 按需开启「开机启动」。登录 Windows 后进入托盘；关闭主窗口继续后台防护。

受保护会话启动时显示校验浮窗，展示检测步骤、当次 IPv4 和锁定地址。通过结果保留约 2.2 秒后启动目标；阻断时保留原因及「知道了」按钮。其他模型会话跳过 IPv4 校验弹窗。关闭校验浮窗或按 Esc 取消本次启动。

运行期间 IP 未命中允许列表或三次检测均失败时，暂停受保护 EXE 的联网，独立弹窗显示原因与 IP 对照；程序与窗口保持运行。恢复允许的出口并通过校验后自动恢复联网，提示同步更新。重复轮询同一状态只提醒一次；短暂复核仅显示界面状态。已有回复流可能中断，恢复后由应用重试或手动重新发送。

获取 IPv4 的前两次失败保持静默，第三次失败后显示提醒。窗口打开期间持续显示后台检测轮次、当前尝试和结果，例如「第 2 轮 · 1/3 次 · 检测中」；更新保持当前 IP 显示选择和焦点。点击「知道了」关闭后，后续计数保持静默；联网恢复仍有独立结果提醒。

守护失联或连接过滤发生故障时，为保护连接仍结束受控进程树。先恢复 IP Guard 防护，再手动启动程序。手动停止、取消锁定、解除防护、路径迁移和正常退出保留原有进程处理方式。

### IP 显示

地址默认脱敏，IPv4 保留前两段，例如 `203.0.•••.•••`；IPv6 保留前两组。点击眼睛按钮可显示或隐藏完整地址，覆盖总览、允许地址、诊断与历史及启动浮窗。隐藏状态下，允许地址表单保留真实草稿，可获取并锁定地址；手动编辑前先点击「显示 IP」。

窗口重新打开或隐藏后恢复脱敏，显示状态保持在当前窗口内。脱敏只作用于显示层，检测、比对和配置保存继续使用真实地址。

### 程序预设与参数

| 预设                | 识别方式                                                                                                                |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Claude Code（npm）  | 当前 npm 全局目录中 `@anthropic-ai/claude-code` 包的原生 EXE                                                            |
| Claude Code（原生） | [官方原生安装](https://code.claude.com/docs/en/setup)路径 `%USERPROFILE%/.local/bin/claude.exe`，以及 PATH 中的独立 EXE |
| Claude Desktop      | 官网 / Microsoft Store 官方 MSIX 的当前用户注册清单，或传统安装的卸载注册信息                                           |

每次打开添加窗口都会重新定位。已添加路径显示「已添加」；未找到或定位失败时，可手动浏览。预设只填表，防护由用户手动开启。

点击程序行的铅笔按钮，可修改名称与启动参数。保存后当前进程继续运行，参数在下次从 IP Guard 点击启动时生效；从终端启动使用终端输入的参数。

顶部「停止 Claude 进程树」会结束当前登录用户、当前 Windows 会话中的 Claude CLI、Desktop 及其子进程，覆盖已添加和未添加的实例，执行前会要求确认。

在 PowerShell、CMD 或 Pebrel 中继续使用原来的 `claude` 命令。同一受保护进程树中的版本查询、内置文件搜索等内部调用复用首次许可；另开终端独立启动仍完整校验。

官网和 Microsoft Store 的 Claude Desktop MSIX 版均按官方安装身份定位，版本目录由当前用户注册清单解析。已添加的 Desktop 更新或更换安装来源后，点击程序行的「更新路径」，核对新旧入口并确认，沿用原条目、名称、启动参数、允许 IP 和防护开关。

迁移启用中的防护会结束原受控进程，请先保存会话并关闭新版 Claude。旧目录失效时显示「路径待更新」，此时先完成路径迁移再启动新版；其他受保护程序继续由守护管理。传统非 MSIX 安装保留卸载信息识别和手动选择入口。

### 程序防护与可选增强

每个 EXE 右侧保留原有的程序防护开关。开启后接管启动，执行该会话适用的 IPv4 校验、异常暂停和恢复；关闭时确认结束对应受控进程，再恢复普通启动。运行中根据实际会话显示「IP 防护已生效」「联网已暂停」或「其他模型会话 · 原网络」。

每个程序行中的「本机 IP 防泄露 · 可选增强」独立于基础开关，默认关闭。开启确认后，软件从本机代理入口定位正在运行的 Xray / sing-box 与当前节点，使用核心副本创建独立 HTTP 通道：国内与国外目标统一送至所选代理节点。原代理的大陆直连规则不会复制进这个通道，普通应用仍用原来的分流；无需全局代理或手动导入节点。

专用路由由 IP Guard 管理。切换节点后自动复核并重建；通道断开、配置不可用或出口异常时关闭受控连接、保留应用进程，恢复后继续检查。最后一个程序关闭增强或解除防护后撤销临时通道。仅复制核心可执行文件，凭据只在内存与核心的私有标准输入中传递，原配置和订阅保持。启动接管程序前，需要现有过滤器和出口校验就绪。现有已开启增强的配置，每次启动桌面时先确认建立专用通道；取消时增强联网保持暂停，基础防护继续。

在「防护设置 → Claude 专用代理」选择自动识别，或指定本机 HTTP / SOCKS5 入口以定位核心。下拉选择即保存；手动地址填好后回车或离开输入框保存，无额外应用按钮和确认窗口。首轮支持：v2rayN 的 Xray / sing-box 已知运行目录，以及显式使用绝对 JSON 配置路径的 Xray / sing-box。自动多节点选择组、链式 / 插件节点、本机 / 内网节点、Mihomo 和其他工具暂显示待适配，保持增强暂停，不退回共享分流端口。IPv4 允许列表仍需包含专用节点的实际出口。

软件启动独立核心并验证监听端口属于自身副本，再通过该通道分别查询 Claude AI 与国内 IP 服务，命中允许列表才打开受控业务连接。节点服务端自身的多出口 NAT 仍由周期检测发现；客户端进程树的绕行封锁依赖实验性过滤驱动，加载与恢复仍待隔离实机验收。自动通道与实验驱动的实机联网、故障恢复仍待隔离验收。

受控 CLI 在进程环境和会话级 `--settings` 中使用同一个代理端口，清空 `NO_PROXY` 并由代理解析域名。原 API 地址、模型、密钥和其他配置保持；已有 `--settings` 合并为会话快照，限制为当前用户与 SYSTEM 访问。启动失败和正常退出时清理，异常退出残留可在关闭会话后从 `session-settings/` 清理。

新增 CLI 入口默认按启动时的 API / 模型配置识别基础防护范围，旧版明确范围保留；编辑名称与参数保持原范围。DeepSeek 等明确的其他模型会话在普通模式中沿用原网络，Claude 或未知模型按锁定地址校验。某个入口开启增强后，该入口的新会话统一进入过滤，其他入口保持各自选择。旧全模型测试开关已移除；旧配置开启它时，升级先将入口转为明确受控，再移除旧字段并保存 `settings.json.bak`，保持原有效范围。

防护围绕本机请求的出口，国内网站及其他国内服务器 IP 的正常查询保留。普通防护继续使用周期探测和暂停机制，存在发现窗口；严格命令过滤的实机加载与恢复仍待隔离系统验收。该增强项只覆盖被接管的 EXE 与常规本机子进程，浏览器网页和官方 Claude 浏览器插件使用各自的网络设置。

按原范围放行的其他模型会话使用本地 CLI 副本，保留同一终端、工作目录和用户配置，原安装文件及代理设置保持。副本关闭自身更新，由原 CLI 安装更新后的新版本生成下一份副本。

**本地中转的严格出口仍有缺口。** 当前能识别它所声明的模型范围，强制固定出口模式仅支持固定通道可达的远程 API 入口。检测到本地 / 内网 API 与强制固定出口组合时，会明确拒绝新启动；基本 IP 检测模式仍需用户确认中转自身的真实出口。客户端的 `127.0.0.1` 连接无法证明中转服务后续连接的出口。

命令进程树保护使用实验性 Fort 驱动，HVCI 启用时保持关闭。该驱动曾在验证中造成全机断网，修复后的真实加载与恢复仍待隔离系统验收；本地试用包保留独立确认与恢复入口。

### 锁定与阻断规则

允许地址统一取自 **Claude AI 出口 IPv4**：`https://claude.ai/cdn-cgi/trace`。获取按钮、启动校验、后台轮询和检测卡片共用结果，检测网络栈沿用系统代理。

| 状态                                   | 处理方式                                |
| -------------------------------------- | --------------------------------------- |
| IPv4 命中允许列表且系统防护就绪        | 允许启动，继续后台监测                  |
| IPv4 未在允许列表中或三次获取均失败    | 阻止新启动，暂停已有程序联网，保留进程  |
| IPv4 恢复命中允许列表                  | 自动恢复已有程序联网                    |
| 地址未锁定或守护离线                   | 保持受控应用的启动拦截                  |
| IPv6、网卡或其他诊断异常               | 展示状态与风险提示，地址授权仍依据 IPv4 |
| 明确的其他模型会话，且严格命令增强关闭 | 使用原网络，不参加 IPv4 暂停与恢复      |

- 默认每 2 秒发起查询，锁定前可设置 1–60 秒间隔。未取得有效公网 IPv4 时最多顺序请求三次，每次最多 4.5 秒，两次重试分别等待 250ms、500ms，总等待约 14.25 秒。变化发现时间还受请求耗时和系统调度影响。
- 网络断开、网卡、Wi-Fi、路由和电源变化先暂停受保护 EXE 联网，再触发 IPv4 复核。超时、网址不可达、证书错误、重定向、空响应或 IPv6-only 返回均可触发重试，证书和公网 IPv4 校验保持开启。首次获取失败后也暂停联网；三次均失败或结果过期时继续断网并保留进程。
- 每次重试刷新 IPv4 专用会话的代理状态、DNS 缓存和连接。主界面记录暂停 / 恢复，启动浮窗显示第 2/3、3/3 次进度；新启动等待最终结果。取得有效 IPv4 后立即比较允许列表，未命中时持续断网，命中后恢复已有程序联网。
- 联网过滤使用 Windows WFP，按受保护 EXE 路径覆盖 IPv4、IPv6、回环代理及已有连接的重新授权。同路径实例共用规则；其他 EXE 的外部工具联网独立，需要单独添加为受保护程序。此模式继续使用主动公网探测，远端代理内部换出口存在发现窗口。
- 允许列表支持换行、英文 / 中文逗号或分号分隔。升级时旧单 IP 自动转为列表，保留锁定和防护开关，并通过 `settings.json.bak` 保留迁移前配置。回退旧版前请恢复相应旧格式备份。
- 取消锁定需要确认，会停止受保护程序并封锁连接；重新锁定后再手动启动。
- 托盘退出会结束受保护进程，启动拦截继续保留。要恢复普通启动，请先解除防护或使用恢复工具。
- 目标程序使用独立代理时，请确认其实际出口与检测结果一致。

## 命令过滤与历史独立出口

「防护设置 → 严格命令防护（实验）」保留驱动安装、故障修复和独立恢复。增强开关只位于对应程序行，上游使用通用代理设置。严格驱动曾发生全机断网，修复后的加载与恢复仍待隔离系统验收，建议仅在独立测试机启用。

### 已部署的独立节点

升级保留旧版已启用的节点、核心和代理策略，只有实际存在独立出口时显示其管理面板。新增强不要求该方案。需要切换时，先保存并关闭各入口的增强，取消 IP 锁定，再点击「改为跟随当前网络」，核对新的通道地址后重新锁定。

节点与核心保存为独立快照，后台检测和受保护程序共用固定通道。受保护 EXE 只允许 IPv4 TCP 访问专用回环代理端口；直连、其他代理端口、IPv6 和 UDP 保持封锁。业务连接仅在允许 IPv4 校验通过后转发；网络恢复后继续复核并自动恢复联网。独立核心退出时保持断网，可点击「重启通道」恢复，程序保留运行。

支持当前生成配置中的普通 Xray / sing-box 单节点。多节点自动选择组、链式代理、外部插件、外部证书文件及跳过 TLS 证书验证的配置会被拒绝。更换固定节点时，先取消锁定、关闭固定出口，再导入和启用；订阅或凭据更新后也需重新导入。

节点凭据使用 Windows 保护的 Electron safeStorage 加密保存，核心配置经标准输入传递。代理服务器域名通过独立 DNS 引导解析，目标域名通过固定节点查询 Cloudflare DoH 并限定 IPv4。Desktop 使用[固定代理策略](https://claude.com/docs/third-party/claude-desktop/network-proxy)，要求支持该策略的版本；Code 使用[代理环境变量](https://code.claude.com/docs/en/network-config)。已有机器策略或 PAC 冲突会明确报告，原策略保留；关闭模式或执行恢复工具时恢复本工具持有的代理值。

固定节点的公网 IPv4 稳定性由节点服务端保障；供应商内部 NAT 或分流更换出口时，仍由后台检测发现。过滤范围为明确保护的 EXE 路径，其他 EXE 的工具、Cowork 虚拟环境、SSH 远端与系统浏览器使用各自网络路径。

旧全局命令过滤开启时，升级将当时已启用的程序映射为各自增强开启，并保存配置备份。其余入口默认关闭增强。切换会结束受控会话，请先保存工作。回退到 0.9.x 前，请先关闭固定出口，或使用 0.10.0 及更新版本的恢复工具清理专用策略。

## Claude 网页防护

网页插件只保护 `claude.ai` 及其子域的网页导航和页面请求，按锁定的 IPv4 放行或阻断。Claude in Chrome / Edge 的官方插件、浏览器代理、WebRTC 与其他网站保持原设置。

### 安装与更新

1. 在「防护设置 → Claude 网页防护」点击「准备安装扩展」，注册网页连接并打开扩展目录。
2. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`，开启开发者模式，加载上述目录。也可解压 `IP-Guard-Browser-<版本>.zip` 后加载。
3. 保持桌面 IP Guard 运行并锁定地址，插件校验通过后直接访问 Claude 网页。页面的「打开 Claude」「返回 Claude」同样直接进入 Claude。
4. 桌面显示已安装 / 正在运行及待更新状态；常规更新后覆盖扩展目录并点击重新加载。

**从 0.12.x、0.13.0–0.13.3 升级：先移除旧 IP Guard 扩展，再加载新版。** 这一步释放旧版本持有的浏览器代理和 WebRTC 设置。保留官方 Claude 插件；此前被暂停时，在扩展管理页重新启用。每份已安装旧扩展的资料分别处理，新版启动会提示能确认旧权限或旧版本的标准资料；登记信息缺失时，请按上述步骤手动清理。自定义资料请手动检查。

### 网页访问判断

网页连接独立通过系统代理查询 Claude AI 出口，避免借用 EXE 增强通道的检测结果。IP 命中允许列表、桌面在线且结果新鲜时放行；未锁定、失联、结果过期或 IP 异常时，撤销网页放行并中断已打开的 Claude 页面，未发送内容可能丢失。后台扩展发起的请求不作为 Claude 网页请求拦截，官方插件的启停及联网保持原样。

权限仅保留 Native Messaging、Claude 域名与请求规则、存储和重连定时器。新版没有 proxy、privacy 或 management 权限。地址继续默认脱敏并保留前两段；深浅主题和插件更新提醒保留。[扩展说明](apps/browser-extension/README.md)。

旧专用 Chrome 的 EXE 防护继续移除，账号资料和目录保留；它与网页扩展的域名判断分别处理。npm、原生 CLI 与 Desktop 的程序开关及可选增强保持。

## 网络诊断

「Claude 检测」接入 [Net.Coffee](https://ip.net.coffee/claude/) 的公开检测端点，提供国内、Cloudflare、Claude 出口以及地区、ASN、运营商、信任分、安全属性、连通性和 DNS 信息。

- Claude AI 出口随守护轮询更新；其余诊断后台每 5 分钟刷新，也可手动刷新。出口变化后重新检测关联属性。
- IPv6 使用独立地址族请求检测公网、Cloudflare 与 Claude 出口；公网 IPv6 来源为 [ipify](https://www.ipify.org/)。缺少路由、超时或无结果时显示未知。
- WebRTC / UDP 通过公开 STUN 服务采集；本机时区、语言、网络类型等信息在本地展示。Claude 出口历史保存在本机，最多 6 条，可清除。
- 网卡支持自动识别与固定选择，展示在线、断开、缺失或无 IPv4 状态；固定网卡重新接入后恢复识别。
- 风险颜色采用检测来源的公开规则，并配合文字和图标：绿色正常、蓝色提示、黄色需核查、红色异常、灰色未知。

诊断项目独立于 IPv4 授权。普通检测模式在地址匹配时允许 IPv4 与 IPv6；Claude 固定出口模式封锁受保护 EXE 的 IPv6 与 UDP，系统 IPv6 设置保持原样。

## 更新、解除防护与恢复

### 软件更新

每次启动、重新打开托盘实例或从托盘打开窗口时检查 GitHub Releases，也可在「防护设置 → 软件更新」手动检查、下载并确认安装。正在检查、下载或安装时复用当前操作，已下载版本保留安装入口。

GitHub 返回 504 等临时错误或连接中断时，检查最多尝试三次并显示当前次数；重试只刷新更新器自己的连接、DNS 与代理状态。最终失败显示中文原因，原始错误保存在应用用户目录的 `logs/updates.log`。检查失败保留已下载版本的安装入口；版本信息未重新取得时标为「上次检测版本」。更新检查不自动下载或安装。

此前安装了 0.13.x / 0.14.0 本地候选版的用户，请手动安装 v0.12.0 一次，随后继续跟随稳定版更新。

请使用 Releases 构建版绑定仓库更新源。本地构建显示「GitHub 更新源未配置」时，可安装公开发布版本。升级保留允许地址、锁定状态和程序列表；原生组件按版本隔离并进行握手核对。

### 解除与恢复

- **单个程序**：关闭对应防护开关，会结束该受控进程树并移除自有启动拦截和防火墙规则。
- **整体恢复**：从托盘退出后，运行安装目录的 `resources/recover.cmd` 并确认管理员授权。工具移除当前用户的拦截、规则和登录任务，原配置备份为 `settings.json.recovery.bak`。
- **卸载**：卸载器调用相同恢复逻辑。请使用启用防护的同一 Windows 账户解除或卸载。

### 配置与日志

数据目录：`%LOCALAPPDATA%/IPGuard/`。

| 文件                                       | 内容                                          |

## 常见问题

### 启动按钮呈灰色

查看程序行的条件提示，依次确认管理员权限、守护连接、允许 IP 已锁定，以及程序防护开关已开启。

### 提示开启 Windows 防火墙

点击软件内的「打开 Windows 防火墙」，进入「Windows Defender 防火墙属性」，将域、专用、公用三个选项卡中的防火墙状态设为启用，确定后重试。也可按 Win+R 输入 `wf.msc`。

### 登录后没有主窗口

自启动进入托盘，可双击托盘图标打开主窗口。「防护设置 → 应用」按实际登录任务显示启用、等待下次登录或失败状态；任务失效时可点击「重新设置」。若托盘也没有图标，可在任务计划程序中检查当前用户的 `IPGuard.*` 登录任务及执行记录。

### 原生组件缺失或版本不匹配

保存会话并退出旧实例后，完整安装同一版本。在侧栏核对实际组件版本；组件目录为安装目录下的 `resources/native/<版本>/`。

### 某些程序无法接管

当前面向普通 Win32 EXE 与已注册 MSIX 主应用，按完整路径区分目标。反作弊、反调试或受保护进程可能拒绝接管。普通子进程由 Job 管理；独立服务、WMI 或既有代理代发连接时，需要识别并管理实际执行程序。

网络变化处理采用用户态事件与轮询，存在采样、请求和调度延迟。具体终端与程序环境的兼容情况可通过 Issues 反馈。

## 开发构建

技术栈为 TypeScript、React、Electron 与 C#，使用 Vite+ 统一构建工具链。Win32 使用路径级 IFEO，MSIX 保留包身份；Job 与租约管理目标进程树。

构建环境：Windows x64、Node.js 24.22.1、pnpm 12.15.0，以及 Windows 自带的 .NET Framework 4.x 编译器。

```powershell
git clone https://github.com/chxcodepro/ip-guard.git
cd ip-guard
npx --yes pnpm@12.15.0 install
npx --yes pnpm@12.15.0 exec vp run dev
```

构建安装包与网页扩展 ZIP：

```powershell
npx --yes pnpm@12.15.0 exec vp run package:desktop
```

输出目录为 `apps/desktop/release/`。开发模式管理当前账户的防护配置，启用真实防护需要管理员权限；调试前请保存会话并退出已安装实例。

外部命令的进程树联网限制见[控制层与验证记录](apps/desktop/experiments/process-network/README.md)。v0.12.0 包含默认关闭的实验增强；安装包只放置驱动文件，安装和启用需另行确认，隔离实机验收仍待完成。

### 项目结构

```text
apps/
  web/                React 桌面界面
  desktop/            Electron 主进程、原生守护与安装配置
  browser-extension/  Claude 网页防护扩展
packages/
  electron/           IPC 契约与共享类型
  ui/                 共享组件与主题
  config/             TypeScript 配置
scripts/              版本管理工具
```

### 发布流程

1. 运行 `pnpm run version:app 0.9.2`，同步应用、原生组件与扩展版本。
2. 提交并推送代码，在对应提交发布同版本标签的 Release，例如 `v0.9.2`。
3. 等待 [Build Windows release](https://github.com/chxcodepro/ip-guard/actions/workflows/release.yml) 工作流完成，安装器、网页扩展 ZIP 与更新元数据将自动附加到 Release。

GitHub 构建自动绑定当前仓库更新源。更新记录见 [CHANGELOG.zh.md](CHANGELOG.zh.md)。
